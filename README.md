## Verify locally

Run `python tools/check_release.py` to verify the file set, sizes and SHA-256 hashes against `release-manifest.json`. This command never publishes anything. Serve only `site/` on loopback for a local preview; directory contents are intended public candidates, not an authentication system.

## Release control

No publication approval is contained in this package. Overall design approval is separate from authorization to expose the exact files publicly.

The included workflow is dormant until separately uploaded and configured after authorization. It has only a manual `workflow_dispatch` trigger, defaults publication authorization to false, checks the owner actor and exact approved site digest, disables persisted checkout credentials, and uploads only `site/`. Merely changing private source or pushing a commit does not trigger this workflow.

After explicit owner authorization for the repository and release, select GitHub Actions as the Pages source. The workflow deliberately does not auto-enable Pages. The owner manually runs it with publication authorized and the reviewed site SHA-256. Repository collaborators must not bypass the documented owner approval process. A hash record is an integrity check, not proof of human consent by itself.

See `PUBLIC-UPDATE-POLICY.md`. No private application repository needs to become public.

W3 uses the coming-soon email option. No provider form, email input or signup link is enabled. The public feeds are intentionally empty because no milestone is approved AND published. Private proposal queues, source registries, preview-only feeds, development builders and review files are excluded. Future milestone ingestion remains a separate private review process.
